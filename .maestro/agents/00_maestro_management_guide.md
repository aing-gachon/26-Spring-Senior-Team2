# 📁 .maestro 기반 프로젝트 문서 및 추적 관리 가이드 (Agent 미사용 시)

이 문서는 역할을 분담하는 특수 에이전트(Agent)들을 일시적으로 사용하지 않고, 수동으로 프로젝트의 변경 사항과 작업 진척도를 완벽히 추적 및 관리하기 위한 **수동 운영 매뉴얼**입니다.

## 1. `.maestro` 폴더의 목적
강화학습 파이프라인 프로젝트는 코드의 변화뿐만 아니라, 하이퍼파라미터 하나, 이미지 전처리 픽셀 한 조각의 변화가 전체 성능을 좌우합니다. 
따라서, `.maestro` 폴더는 단순 소스 코드를 넘어 **"우리가 왜 이 코드를 고쳤고, 어떤 실험 결정을 내렸는지(Decision History)"**를 문서화하는 중앙 통제실이자, **이론적 근거 문서 보관소**입니다.

---

## 2. 수동 관리 파이프라인 (변경사항 추적 후 저장 절차)
코딩, 디버깅, 혹은 실험(학습) 루틴을 한 번 돌릴 때마다 다음 3단계를 수행하여 기록을 영구 보존합니다.

### 🍅 Step 1. 데일리 리포트 (`daily_reports/YYYY-MM-DD/`) 작성
- **목표**: 쏟아지는 파편화된 기억들을 날짜별로 캡슐화.
- **수행 방법**:
  1. 오늘 작업이 개시되면 `.maestro/daily_reports/오늘날짜/` 폴더를 생성합니다.
  2. 그 안에 `daily_report.md` 를 생성하여 **오늘 수정한 파일**, **데이터셋 필터 기준을 바꾼 이유**, **발생한 에러(OOM 등)와 해결책** 등을 서술형으로 털어놓습니다.

### 🍅 Step 2. 전체 버저닝 (`changelog.json`) 영구 갱신
- **목표**: 프로젝트의 거시적인 흐름과 최종 변경된 코드 내역 파악 및 타 개발자와의 연동성(Parsing) 향상.
- **수행 방법**: 일과가 끝나기 전 `.maestro/changelog.json` 문서를 엽니다.
  - JSON 배열 최상단이나 끝단에 새로운 `{ }` 객체를 추가합니다.
  - `"timestamp"` 키 값에 현재 수정 시간을 기입합니다.
  - `"changes"` 객체 내부에 수정된 내용을 배열(`[ ]`) 형태로 명확히 담아 기록합니다.

### 🍅 Step 3. 로드맵 상태 보드 (`progress.md`) 체크
- **목표**: 길을 잃지 않기 위한 현재 좌표 및 남은 마일스톤 시각화.
- **수행 방법**: 프로젝트가 한 단계 진척되었다면 표(Table)에 `✅ 완료` 와 개발 이력을 기입하고, 남은 `To-Do` 리스트에서 해야 할 일들을 수정 혹은 삭제합니다.

## 3. 외부 기술 문서 및 참조(Reference) 연동 프롬프트 룰 (Prompt Rule)

프로젝트 내부 곳곳에 흩어져 있는 `.md` 설명서들을 유기적으로 불러와 안전한 코드를 작성하기 위한 **법칙(Prompt)**입니다. 향후 이 프로젝트에 새롭게 추가되는 **모든 마크다운(`.md`) 파일**에도 에이전트(혹은 작업자)는 이 규칙을 의무적으로 상기하고 적용해야 합니다.

### 📚 3-1. 언제, 어떤 문서를 참조하여야 하는가?

**1️⃣ 연구적/이론적 구현 시점 (`.maestro/` 내 연구 문서 참조)**
- **[예시] `.maestro/관련 논문.md`**: 보상 체계(Reward Function) 알고리즘을 변경하거나, 모델 훈련 하이퍼파라미터(TD error 보정 비율 등)를 설정할 때, **절대 임의로 코드를 수정하지 말고 반드시 의사결정 전 `관련 논문.md`를 열람**하여 논문의 의도 및 가이드라인과 코드가 일치하는지 증명해야 합니다.

**2️⃣ 시스템 뼈대 및 구조적 의사결정 시점 (`Docs/` 폴더 문서 참조)**
- **`Docs/Architecture_Notes.md`**: 전처리기가 어떻게 돌아가고 어떻게 Agent의 State 텐서 형태로 변환되는지 등, 거시적인 **네트워크 아키텍처 스펙**을 수정하거나 입출력 차원(Shape) 에러를 고쳐야 할 때 읽습니다.
- **`Docs/pipeline.md`**: 코드 전체의 **워크플로우(Workflow)와 파이프라인의 생애주기** 작동 원리를 파악할 때 참고합니다.
- **`Docs/Directory Structure.md`**: 새로운 스크립트를 생성하거나 함수를 빼서 다른 폴더로 이동시킬 때, 이 행동이 기존의 **파일 분리 규칙**을 헤치지 않는지 크로스체크 하기 위해 읽습니다.

### 🤖 3-2. 모든 Agent / 작업자에게 부여되는 심층 수칙 (Universal Action Prompt)
> **"업무에 착수하기 전, 자신의 역할과 연관된 위치의 `.md` 문서를 스캔(Scan)하는 것을 최우선(1순위)으로 삼으십시오. 특히 `.maestro` 폴더에는 알고리즘 논문 등 이론적 배경이 되는 근거 자료가 존재하며, `Docs` 폴더에는 프로젝트의 시공 설계도가 들어있습니다. 각 역할에 맞는 `.md` 파일이 추가로 존재한다면 무조건 그 문서들의 내용부터 선행 학습(View File)한 뒤 코딩이나 유지보수를 결정지어야 합니다."**
